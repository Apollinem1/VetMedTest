# Интеграции с базами клиник

Как подключаем клиники, которые уже работают в 1С, alfaCRM и других системах.

---

## Подходы

| Подход | Описание |
|--------|-----------|
| **Синхронизация** | Выгрузка из их системы → маппинг → импорт в MedVet. Данные живут у нас. Очереди (Laravel Queue). Нужны: формат обмена, маппинг сущностей, стратегия при конфликтах. |
| **Прямое подключение** | Чтение/запись в их БД через адаптер. Используем только при стабильном внешнем API и договорённости с клиникой. |

В приоритете — синхронизация.

---

## Сценарии

- **Импорт в MedVet** — разовая или периодическая выгрузка: клиенты, питомцы, приёмы → наша БД.
- **Двусторонняя синхронизация** — запись из MedVet уезжает в 1С/alfaCRM; изменения оттуда подтягиваются к нам.
- **Только чтение** — показ данных из их системы без копирования (редко).

---

## Целевые системы

| Система | Примечание |
|---------|------------|
| 1С (вет.) | Уточнить линейку: Кабинет ветврача, Управление ветклиникой и т.д.; наличие API/выгрузок. |
| alfaCRM | Обычно MySQL; проверить внешний API. |
| Другие | Добавлять по запросам клиник. |

---

## Что проработать при внедрении

- Список и приоритет систем.
- По каждой: способ обмена (файл/API), формат, частота, маппинг сущностей.
- Источник правды при конфликтах: наша БД или их система.
- Очереди и воркеры для фоновой синхронизации.
