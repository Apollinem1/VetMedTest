# Модели данных

PostgreSQL. PK везде — UUID. Soft delete и audit — см. [[02 - Стек и архитектура#Решения по БД]].

**Обозначения:** PK — первичный ключ, FK — внешний ключ, ? — nullable. [soft] — есть deleted_at, [audit] — пишем в audits.

---

## Auth & Users

**users** [soft]  
id (uuid), email (unique), phone (unique?), password?, status (active|pending|blocked), email_verified_at?, deleted_at?, created_at, updated_at.  
Роли/пермишены — таблицы Spatie (roles, permissions, model_has_roles, …).

**user_profiles**  
id, user_id (FK→users), first_name, last_name, middle_name?, avatar?, timezone, locale.

**vet_profiles**  
id, user_id (FK→users), specialization?, bio?, education? (jsonb), licenses? (jsonb).

**personal_access_tokens** — стандартная таблица Sanctum.

---

## Clinics

**clinics** [soft]  
id, name, legal_name, inn?, ogrn?, license_number?, status (pending|active|suspended), owner_user_id (FK→users), logo?, deleted_at?, created_at, updated_at.

**branches** [soft]  
id, clinic_id (FK→clinics), name, address, city, lat?, lng?, phone?, email?, working_hours? (jsonb), is_active, external_id_2gis? (id в 2ГИС для плашки), deleted_at?, created_at, updated_at.

**vet_branches**  
id, vet_id (FK→users), branch_id (FK→branches), position?, active_from (date), active_to? (null = работает). При проставлении active_to — отзыв PetAccess этого врача в этой точке.

---

## Companies (B2B)

**companies** [soft]  
id, name, legal_name?, inn?, type (breeder|farm|enterprise|other), owner_user_id (FK→users), deleted_at?, created_at, updated_at.

**company_employees**  
id, company_id (FK→companies), user_id (FK→users), role (admin|employee), is_active.

---

## Pets

Полная спецификация модели питомца: **[[06a - Модель питомца (полная)]]**.

**pets** [soft] [audit] — кратко: владелец (user или company), status (active|deceased|transferred|archived), имя, вид, порода, пол, дата/год рождения, окрас, фото, приметы, заметки; чип (номер, дата, место), ветпаспорт, родословная, внутренний id; кастрация, вес, размер, группа крови; дата смерти, заметки о передаче; для B2B — группа, загон, мать/отец; страховка; предпочитаемые вет/точка; опционально денормализация next_* дат; timestamps, soft delete. Один из owner_user_id или owner_company_id обязателен при status = active.

**pet_access** [audit]  
id, pet_id (FK→pets), granted_to_id (FK→users), granted_by_id (FK→users), branch_id? (FK→branches), access_type (vet|family), expires_at?, revoked_at?, created_at.

---

## Medical Records

**visits** [soft] [audit]  
id, pet_id (FK→pets), vet_id? (FK→users), branch_id? (FK→branches), clinic_name_raw?, visit_date, weight?, temperature?, symptoms?, diagnosis?, recommendations?, source (vet_system|owner_reported|ocr_auto|imported), is_verified (bool), deleted_at?, created_at, updated_at.

**vaccinations** [soft] [audit]  
id, pet_id, vet_id?, branch_id?, name, batch_number?, date, next_date?, source, deleted_at?, created_at, updated_at.

**deworming_records** [soft] [audit]  
id, pet_id, vet_id?, branch_id?, drug_name, dosage?, date, next_date?, source, deleted_at?, created_at, updated_at.

**tick_treatments** [soft] [audit]  
id, pet_id, vet_id?, branch_id?, product_name, dosage?, date, next_date?, source, deleted_at?, created_at, updated_at.

**prescriptions** [soft] [audit]  
id, visit_id? (FK→visits), pet_id, vet_id?, drug_name, dosage?, frequency?, duration?, issued_at, expires_at?, scan_path? (S3), source, deleted_at?, created_at, updated_at.

**allergies** [soft]  
id, pet_id, allergen, reaction?, severity? (mild|moderate|severe), detected_at?, deleted_at?, created_at, updated_at.

**chronic_conditions** [soft]  
id, pet_id, name, diagnosed_at?, status (active|in_remission|resolved), notes?, deleted_at?, created_at, updated_at.

**pet_documents**  
id, pet_id, uploaded_by (FK→users), type (passport|pedigree|analysis|scan|other), title, file_path (S3), source (owner_uploaded|vet_uploaded|ocr_source), created_at.

---

## Billing

**plans**  
id, name, target (owner_person|owner_company|clinic), price, billing_period (monthly|yearly), features (jsonb; для B2B — ступени по кол-ву животных), is_active.

**subscriptions**  
id, subscriber_type (полиморфно: user/company/clinic), subscriber_id, plan_id (FK→plans), status (active|cancelled|past_due|trialing), starts_at, ends_at?, cancelled_at?, created_at, updated_at.

---

## Notifications

**notification_settings**  
id, user_id (FK→users), channel (push|email|sms), type (vaccination_reminder|deworming_reminder|appointment_reminder|access_request), is_enabled.  
Сами уведомления — Laravel notifications.

---

## Audit

**audits** (owen-it/laravel-auditing)  
id, user_type, user_id, event, auditable_type, auditable_id, old_values? (jsonb), new_values? (jsonb), url?, ip_address?, user_agent?, created_at.  
Используется для: visits, vaccinations, deworming_records, tick_treatments, prescriptions, pet_access, pets.
